# 钢铁防线开发交接

## 目录与依赖

```text
src/
  main.ts       应用状态机、界面动作、整备流程、固定步长主循环
  data.ts       武器、敌军、技能、被动、区域、地图与路线参数
  math.ts       坐标、随机数、扫掠检测与圆形碰撞
  world.ts      九种地图生成、地形对象、碰撞、射界与 A* 寻路
  battle.ts     可测试的战斗状态、统一更新入口与事件
  systems/
    tank.ts     坦克移动、车体转向与独立瞄准
    weapons.ts  炮口、主炮、连续弹道与命中顺序
    enemies.ts  AI、寻路避让与 Boss 阶段
    abilities.ts 主动技能、维修站与持续效果
    damage.ts   护盾耐久、范围伤害与地形破坏
    waves.ts    波次、出生预警与延迟攻击
  models.ts     原创程序模型、共享资源与按材质合并网格
  render.ts     Three.js 场景、跟随镜头、特效、预警和装备预览
  input.ts      键鼠、双摇杆、多指指针归一化
  audio.ts      原创 Web Audio 声音、环境与音乐合成
  campaign.ts   战役地图组合、强化与一次性交易
  save.ts       版本化存档、校验、设置与本地纪录
  ui.ts         所有菜单、HUD、小地图、装备及交互
  style.css     工业战术视觉与横屏响应式布局
tests/
  core.test.ts  无渲染规则回归
  pilot.ts      只产出正常战斗输入的验收驾驶员
  campaign-run.ts 六战连续仿真与普通整备
  browser.ts    浏览器实际页面的输入、暂停、检查点和全流程验收
qa.html         开发验收台，不随生产构建发布
dist/           可部署的静态网站
```

Three.js 负责通用渲染；Vite 和 TypeScript 负责开发与构建。核心玩法不依赖游戏引擎模板。`package-lock.json` 锁定依赖。

## 状态与系统关系

`main.ts` 是唯一的应用流程拥有者。菜单、路线、奖励、商店和暂停不推进战斗。仅 `playing` 状态以 1/60 秒固定步长调用 `Battle.update()`；渲染帧与模拟帧分离。高刷新率下，一次性按键在存在模拟步时才消费。

`Input.read()` 将键鼠或两个独立指针映射为同一个 `BattleInput`。`Battle` 不依赖 DOM、音频或 Three.js，可以在 Node.js 内完整运行。模拟通过事件队列告知应用播放声音、显示提示或进入结算。`Renderer` 读取模拟状态建立模型和特效，不决定命中。

`World.objects` 是地图碰撞、射界、地形耐久和视觉的统一真相。地图每次破坏递增 `revision`，敌军在下一次更新时重新寻路。装饰碎片没有碰撞。坦克移动采用按轴分步的圆形底盘包络，冲刺沿同一规则处理。

## 坐标和射击边界

世界单位是米，时间单位是秒，地面为 x/z，Three.js 的 y 表示高度。角度使用弧度，`atan2(dx, dz)` 对应沿 +z 的模型前方。车体朝向和炮塔朝向独立保存。

射击先由炮塔角度及武器长度计算炮口，再扫掠检查车体到炮口的实体遮挡。炮口受阻时不会在墙后生成子弹。每颗弹丸在前一位置和新位置之间进行连续检测，比较最近墙体和最近车辆的交点比例。磁轨炮用命中 ID 集合避免一颗弹反复伤害同一辆车。

直击伤害和范围伤害分别结算，直击对象排除在同一次爆炸之外。伤害统一进入 `damage()`：明确减伤与弱点倍率、护盾吸收、耐久扣除、击毁及奖励。基地通过独立入口处理固定装甲和护盾。环境连锁在物件销毁闩锁与最大深度限制下执行。

## 新增内容

**武器**：在 `data.ts` 增加 ID 与射速、弹速、射程、伤害、范围、穿透、价格；在 `models.ts` 的 `weaponModel()` 增加对应发射结构；如弹道不属于实体弹丸或电弧，需要在 `systems/weapons.ts` 添加独立规则；在 `audio.ts` 增加声音，在 `ui.ts` 的图标字典增加实心剪影。商品预览使用同一套真实三维模型离屏渲染，无需另画不一致的缩略图。

**敌人**：增加 `EnemyDef`，定义目标、轮廓、半径、速度、武器与奖励；在 `tankModel()` 增加外形，在 `updateEnemy()` 添加特有行为，并把类型加入相应阶段的波次池。出生位置必须通过 `pending → spawn warning → spawn`，保留 3.5 秒预警。

**技能与强化**：添加数据说明及冷却，在技能入口或明确的模拟钩子里实现效果，避免在渲染中改战斗状态。强化逻辑用 `has()` 查询；改变耐久、护盾上限时同时维护 `maxHp()` / `maxShield()` 和整备应用逻辑。

**地图**：在 `MAPS` 注册区域与 pattern，在 `World.generate()` 编写结构。通过 `add()` 添加实体，保留基地附近、出生入口和中央救援线。用 `world.path()` 验证所有出生点、基地及维修点。区域环境、地面纹理和外围设施由 `render.ts` 区分。

## 平衡修改

优先调整 `data.ts` 中武器间隔、敌军组合、速度与威胁；`beginWave()` 控制数量和出生节奏。基地伤害倍率在 `damageBase()` 中，修改时同步更新教程和 README。不要只提高敌军生命制造难度。

战役目标节奏为 15–25 分钟。`tests/campaign-run.ts` 给出固定种子的连续战斗时间参考，测试驾驶员会读取完整战场并精准避弹，因此它的存活率不代表新玩家难度。真实玩家平衡仍需多人实测。

## 存档与防重

存档只保存 `Run`，不保存正在飞行的弹丸和临时计时器。读取时先验证地图、武器、技能、强化和数值范围；损坏数据返回空检查点。`routeStage` 和 `eventStage` 防止反复回到路线或事件刷恢复资源。

商店使用单次商品 ID 与 `Transactions`，余额检查和替换决定完成后才扣款；奖励界面只接受当前实际提供的强化 ID。结算先设置 `outcome`，再清空弹药、预警和出生队列，避免重复结算和胜利后伤害。

## 性能与测试

共享几何与普通材质保留缓存；静态装甲按材质合并，动态履带、炮塔、发光与 Boss 部件保持独立。临时弹丸、特效、音频节点应在生命周期结束后移除和释放。新增临时效果时沿用现有资源归属约定。

`npm test` 验证碰撞、射击、地图、伤害、事务与存档。`npx tsx tests/campaign-run.ts` 以正常输入完成六战。开发浏览器访问 `/qa.html` 可重现集成检查；`?qa=1` 仅在 Vite 开发环境启用明确标注的 12×自动驾驶分支，生产构建不包含测试驾驶员。

完整设备覆盖、已知限制和实测结果以 `测试报告.md` 为准。
